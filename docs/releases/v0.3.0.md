Madoの画面が使う内部APIのほぼすべてを、アクセストークンから使えるようになりました。トークンには機能ごとの操作（読み取り・送信・編集・削除・実行・管理）と、許可する接続・Namespaceを選びます。あわせて、トークンまわりの古い形式の受け付けをやめ、既存のトークンはDBの更新で新しい形へ移します。

## 変更点

- `/api/internal/*`を`Authorization: Bearer`のアクセストークンで使えるようにしました。Storage・接続・README・Notes・タグ・お気に入り・DataLineage・ジョブ・容量・単価・設定・ユーザー・アクセストークン・監査の各機能で、操作ごとに許可します。権限表に無いAPIはトークンからは使えません。
- トークンの管理（`service_accounts:manage`）を許可したトークンは、自分の権限・接続・Namespace・有効期限の範囲内でだけ、トークンを発行・変更・再発行・削除できます。ユーザー管理は、全権限・全接続・全Namespaceを持つトークンに限ります。
- 連携API（`/api/mado/`、OpenLineage送信、Prometheus）が確かめるscopeは、選んだ操作から決まります。トークンの入力に`scopes`は含められません。
- 接続は常に一覧で指定します（全接続は`["*"]`）。指定の無いトークンを全接続として扱う古い扱いはなくなりました。
- 二階層の`/api/internal/service-accounts/*` APIを削除しました。トークンの管理は`/api/internal/access-tokens/*`で行います。

## 互換性と更新手順

更新前にDBをバックアップしてください。**この版は古い形式を読みません。** 次の順で更新します。

1. `039_internal_api_tokens.sql`を適用します（表を追加するだけなので、旧版の稼働中に適用できます）。
2. `api-internal`と`api-lineage`を止めて`040_explicit_token_grants.sql`を適用し、両方をこの版で起動します。Webもこの版へ更新してください。
   - 040は既存のトークンを変換します。連携scopeだけのトークンには対応する操作（`lineage:read`→DataLineageの読み取り、`lineage:write`→送信、`metrics:read`→容量の読み取り）を付け、接続を指定していなかった容量トークンには全接続を明示します。持ち主のアカウントが無効だったトークンは、トークン自身を無効にします。
   - トークンの値・IDは変わりません。
   - 040は旧版が読む列を消すため、適用後は旧版へ戻せません。

`media-worker`はこの更新の影響を受けません。v0.1.0から更新する場合は、先に[v0.2.0の手順](https://github.com/aida0710/mado-s3-datacatalog/blob/v0.3.0/docs/releases/v0.2.0.md)に従って`038_access_tokens.sql`を適用してください。

## 配布物

Linux amd64/arm64向けの`mado-api`、`mado-media-worker`、`mado-web`をGHCRで配布します。添付の`mado-v0.3.0.tar.gz`には、digest固定のCompose、設定例、DB更新ファイル、導入手順が入っています。SHA-256チェックサムとビルド証明も公開します。

互換Dataset Registryとその認証トークンは引き続き別途必要です。[ドキュメント](https://aida0710.github.io/mado-s3-datacatalog/)、[内部APIの権限](https://github.com/aida0710/mado-s3-datacatalog/blob/v0.3.0/docs/internal-api-permissions.md)、[ML Tracking連携の仕様](https://github.com/aida0710/mado-s3-datacatalog/blob/v0.3.0/docs/model-tracking-api.md)を参照してください。
