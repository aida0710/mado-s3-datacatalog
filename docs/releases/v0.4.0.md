古い版のデータや呼び出し方を受け付けるために残していた扱いを削除しました。認証は必須になり、接続設定と音声キャッシュの古い形はDBの更新で今の形へ移します。

## 変更点

- `AUTH_MODE=disabled`を削除しました。`AUTH_MODE`は`local`・`oidc`・`hybrid`のどれかを必ず指定します。未指定ではAPIが起動しません。認証主体の無い要求をすべて許可する扱いもなくなりました。
- NotesとREADMEの編集者は、ログインしている人（またはトークン）から決めます。保存の要求に`editor`を含めると400になります。ブラウザに保存していた署名も使いません。
- DataLineageのクエリ`kind`を受け付けなくなりました。`rootKind`を使います（`kind`を送ると400）。
- 旧Access画面のURLの転送を削除しました。知らないURLは「見つかりません」を表示します。
- 配布するedgeの設定から、旧ホスト名の転送（`MADO_LEGACY_HOSTNAME`）を削除しました。
- 接続APIの応答で、古いAPIに合わせて欠けた項目を補う扱いと、旧ブラウザキャッシュの起動時の削除をやめました。

## 互換性と更新手順

更新前にDBをバックアップしてください。**この版は古い形の接続設定を読みません。** 次の順で更新します。

1. `.env`に`AUTH_MODE`（`local`・`oidc`・`hybrid`）があることを確かめます。
2. `api-internal`と`api-lineage`を止めて`041_explicit_connection_settings_media_cache.sql`を適用し、両方をこの版で起動します。Webと`media-worker`もこの版へ更新してください。
   - 041は、接続ごとに欠けている操作の許可・走査・容量集計の設定へ、今の実効値（未設定は`true`）を書き込みます。値は`true`か`false`だけになります。
   - metaか接続の無い音声キャッシュを消します。必要になったときに作り直します。
   - 旧版はAPIの稼働中に設定の無い接続を作れるため、041の適用中はAPIを止めます。
3. 旧ホスト名の転送を使っている場合は、運用中のedgeの設定（Composeと`nginx/edge.conf.template`）にそのまま残してください。新しい配布物の設定へ置き換えると転送はなくなります。

v0.2.xから更新する場合は、先に[v0.3.0の手順](https://github.com/aida0710/mado-s3-datacatalog/blob/v0.4.0/docs/releases/v0.3.0.md)に従って039・040を適用してください。

## 配布物

Linux amd64/arm64向けの`mado-api`、`mado-media-worker`、`mado-web`をGHCRで配布します。添付の`mado-v0.4.0.tar.gz`には、digest固定のCompose、設定例、DB更新ファイル、導入手順が入っています。SHA-256チェックサムとビルド証明も公開します。

互換Dataset Registryとその認証トークンは引き続き別途必要です。[ドキュメント](https://aida0710.github.io/mado-s3-datacatalog/)と[DBの更新手順](https://github.com/aida0710/mado-s3-datacatalog/blob/v0.4.0/db/README.md)を参照してください。
