DataLineageをmado S3 Data Catalogから外しました。データセットと処理の来歴は、兄弟製品のmado ML Trackingが受け持ちます。OpenLineageの受け付け（`api-lineage`と`:8081`）、Dataset RegistryとMarquezへの接続、アクセストークンのNamespaceが無くなります。更新の前に、RegistryとMarquezのデータの控えと、`.env`・Compose・TLS proxyの片付けが要ります。DataLineageの権限だけを持っていたアクセストークンは無効になります。

## 変更点

- **DataLineageの削除**: 画面のDataLineage（グラフ・登録一覧・手動登録）と、Storageの画面にあった「この場所のデータセットの版」の欄を無くしました。APIは`/api/internal/lineage/*`、`/api/mado/lineage/*`、`POST /api/openlineage/v1/lineage`が無くなります。このリリースは、Dataset RegistryとMarquezのデータを読みも消しもしません。
- **`api-lineage`と公開用の入口の削除**: OpenLineageを受けていたプロセス`api-lineage`（`:3001`）と、Webのイメージの`:8081`の入口を無くしました。Composeのserviceは`postgres`・`api-internal`・`media-worker`・Webの4つです。Internetへ公開する入口はありません。
- **環境変数の削除**: `MDC_DATASET_REGISTRY_URL`、`MDC_DATASET_REGISTRY_TOKEN`、`MDC_MARQUEZ_URL`、`MDC_LINEAGE_PORT`、`MDC_OPENLINEAGE_BODY_LIMIT_BYTES`、`MDC_LINEAGE_DB_PASSWORD`、`MDC_API_HOSTNAME`は読みません。残っていても起動は止まりません。
- **アクセストークン**: 権限`lineage:read`・`lineage:send`・`lineage:curate`と、連携scopeの`lineage:read`・`lineage:write`を無くしました。連携scopeは`metrics:read`だけです。Namespaceの指定も無くなり、作成・変更の本文の`namespaces`は受け付けません（400）。Namespaceの候補を返していた`GET /api/internal/access-tokens/namespaces`は無くなり、`GET /api/mado/access-token`の応答から`namespaces`が消えます。
- **ロールと権限**: Viewer・Curator・Operator・Adminから、DataLineageの権限を外しました。ほかの権限は変わりません。
- **接続の一覧のAPI**: `GET /api/mado/connections`を足しました。アクセストークンに許可した接続のID・名前・種類を返します。scopeは問わず、エンドポイントと鍵は返しません。
- **mado ML Trackingとの連携**: mado ML Trackingがこの製品から使うのは、トークン自身の情報（`/api/mado/access-token`）、接続の一覧（`/api/mado/connections`）、容量メトリクス（`/api/mado/metrics/capacity`）になりました。mado ML Trackingは、`s3://`の場所をこの製品の画面で開くリンクを作るために、接続の一覧を使います。使い方は[`docs/model-tracking-api.md`](https://github.com/aida0710/mado-s3-datacatalog/blob/v0.6.0/docs/model-tracking-api.md)にあります。
- **配布物**: リリースの束に`REGISTRY_API_CONTRACT.md`は入りません。

## 互換性と更新手順

更新前にDBをバックアップしてください。このリリースの移行（`046_remove_lineage.sql`）は元に戻せません。v0.5.3へ戻すときは、バックアップからDBを復元します。

v0.4.0以前から更新するときは、先に[v0.5.0の更新手順](https://github.com/aida0710/mado-s3-datacatalog/blob/v0.5.0/docs/releases/v0.5.0.md#互換性と更新手順)を済ませます。

1. **mado ML Trackingを先に更新します。** mado ML Trackingでこの製品のDataLineageの連携（データセットの取り込みと、Runの記録の送信）を使っているなら、その連携を外した版へ先に上げます。古い版のままだと、取り込みと送信が失敗し続けます。
2. **OpenLineageを送っているPipelineを止めるか、送り先を替えます。** 更新の後は`POST /api/openlineage/v1/lineage`を受ける入口がありません。
3. **Dataset RegistryとMarquezのデータを控えます。** どちらもこの製品の外で動かしているサービスです。それぞれのDBのダンプを取り、読めることを確かめてから保管します。この製品のDBにあるのは、S3の接続とRegistryの保存先の対応表（`lineage_storage_bindings`）だけです。要るなら更新の前に書き出します。

   ```bash
   docker compose -f compose.yaml exec -T postgres \
     psql -U postgres -d dashboard -c '\copy lineage_storage_bindings TO STDOUT WITH CSV HEADER' \
     > lineage_storage_bindings.csv
   ```

4. **DataLineageの権限を持つアクセストークンを確かめます。** 移行は、トークンからDataLineageの権限・連携scope・Namespaceを外します。DataLineageの権限だけを持っていたトークンは、できる操作が無くなるので無効になります。ほかの権限も持つトークンは、残りの権限でそのまま使えます。無効になったトークンを残したいときは、更新の後にSettings → Access → Access Tokensで権限を選び直し、有効に戻します。要らなければ削除します。
5. **Composeとイメージを差し替えます。** 配布物では新しい`compose.yaml`に置き換えます。自分のComposeを使っているなら、`api-lineage`のserviceと、Webの`127.0.0.1:8081`のpublish、Webの`depends_on`にある`api-lineage`、`postgres`に渡している`MDC_LINEAGE_DB_PASSWORD`を外します。そのうえで`api-internal`を先に起動し（移行が当たります）、残りを起動します。

   ```bash
   docker compose -f compose.yaml pull
   docker compose -f compose.yaml up -d --remove-orphans api-internal
   docker compose -f compose.yaml up -d --remove-orphans
   ```

   `--remove-orphans`は、Composeから外した`api-lineage`のコンテナを消します。
6. **`.env`から使わなくなった変数を消します。** `MDC_DATASET_REGISTRY_URL`、`MDC_DATASET_REGISTRY_TOKEN`、`MDC_MARQUEZ_URL`、`MDC_LINEAGE_PORT`、`MDC_OPENLINEAGE_BODY_LIMIT_BYTES`、`MDC_LINEAGE_DB_PASSWORD`、`MDC_API_HOSTNAME`です。Registryのtokenは、Registryの側でも失効させます。
7. **公開用のTLS proxyを片付けます。** `127.0.0.1:8081`へつないでいたvhostと、そのhostnameのDNS・証明書・ファイアウォールの許可を外します。
8. **DBのロールを片付けます（任意）。** 移行は、ロール`mado_lineage`からこのDBの権限をすべて外し、ログインを止めます。ロール自体はクラスタ全体のものなので残ります。同じPostgreSQLのほかのDBで使っていなければ、次で消せます。

   ```bash
   docker compose -f compose.yaml exec -T postgres psql -U postgres -c 'DROP ROLE mado_lineage;'
   ```

   ほかのDB（テスト用の`dashboard_test`など）に権限が残っていると、`DROP ROLE`は失敗します。そのDBにも移行を当てるか、そのDBで`DROP OWNED BY mado_lineage;`を実行してからやり直します。
9. **Dataset RegistryとMarquezを止めます（任意）。** 控えを確かめた後、ほかに使っているものが無ければ止めます。

監査ログにあるDataLineageの操作の記録（`lineage.*`）は、そのまま残ります。
